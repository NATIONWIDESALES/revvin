# Meta registration preparation, November 18, 2026

## Implemented
- Signup success sends one non-blocking, authenticated request to meta-capi when the same region, refusal, GPC/DNT and URL gates permit advertising. Consent is resolved during signup and checked again before dispatch. No retry loops.
- Browser and server share `reg_<auth user UUID>` and CompleteRegistration. The isolated frame accepts only a validated registration ID and fixed event names, with existing no-referrer, autoConfig=false, source/origin guards and disposal rules unchanged.
- The endpoint checks the authenticated user's owned, non-demo business and signup age, derives occurrence time from the authenticated user record, validates bounded identifiers and rejects extra fields. No client email, event name or value is accepted.
- fbc is built only after permission from validated session fbclid and the stored first-seen timestamp; an existing valid _fbp is optional. Request headers supply IP and browser type. No email, name, phone, business details or referral data enters the payload.
- SHA-256 normalization helper is tested; SEND_HASHED_EMAIL=false and no payload path includes em. Changing that constant alone does not enable email sharing.
- Privacy disclosure and the duplicate advertising summary are updated. Last updated was already November 18, 2026 and remains that date.
- Missing META_CAPI_ACCESS_TOKEN logs exactly `capi disabled: no token`. Other failures expose no response body, identifiers or credentials.

## Incomplete sending dependency
The Meta integration guidance requires a verified linked service connection and its returned transport contract. No Meta connection is available to this project. Consequently the new endpoint has **no live Meta transport**. Adding the runtime access token alone does **not** enable sending. There is no claimed Graph API version, because the supported connection supplies its version and has not been configured. The pure sender's injected transport is exercised only by tests.

Create the supported connection at https://lovable.dev/connectors/meta_ads/connect?workspace=vEZDexEmR4gLDvDNVyWY, then link it and supply its verified contract. META_CAPI_ACCESS_TOKEN and optional META_CAPI_TEST_EVENT_CODE belong in Project Settings > Secrets. No token should be pasted into chat.

No migration or persistent idempotency claim was added. Repeated requests have the same event name and ID, allowing Meta's 48-hour deduplication once sending is connected. They are not globally at-most-once. Signup without an immediate authenticated session cannot call this authenticated endpoint; no delayed replay was introduced.
